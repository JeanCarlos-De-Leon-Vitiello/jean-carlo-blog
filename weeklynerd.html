Killian Valkhof

Stop using JS.. In the future

Wat hij vertelde

Tijdens de Weekly Nerd vertelde Killian Valkhof dat developers nog te veel JavaScript gebruiken terwijl HTML en CSS tegenwoordig veel mogelijkheden hebben. Zijn belangrijkste boodschap was:

kies altijd de minst krachtige oplossing die nodig is

Browsers kunnen veel sneller omgaan met HTML en CSS dan met JavaScript. Zodra je JavaScript gebruikt, moet de browser extra werk doen om alles uit te voeren en te renderen. Hij vertelde ook dat oude websites vaak nog steeds blijven werken in moderne browsers. Dat komt doordat browsers achterwaarts compatibel zijn gemaakt. Oude code blijft dus ondersteund zodat websites niet ineens kapot gaan wanneer een browser update krijgt. Als laatst liet hij voorbeelden zien van functionaliteiten die vroeger alleen met JavaScript mogelijk waren, maar nu gewoon met CSS en HTML gemaakt kunnen worden.

Belangrijke inzichten

  • Custom switch zonder JavaScript

    Met appearance: none kan je de standaard styling van een input verwijderen. Hierdoor verandert een checkbox eigenlijk in een leeg element dat je volledig zelf kunt stylen. Door vervolgens pseudo-elementen zoals ::before te gebruiken kan je bijvoorbeeld een bolletje maken binnen de switch. Met :checked kan je de staat aanpassen zodra iemand erop klikt. Hierdoor kan je een interactieve switch maken zonder één regel JavaScript te gebruiken. Killian vertelde hierbij ook dat veel developers nog denken dat forms moeilijk te stijlen zijn. Volgens hem was dat vroeger misschien waar, maar tegenwoordig bieden browsers veel betere mogelijkheden om formulier-elementen aan te passen.

  • Smooth scrolling zonder JavaScript

    Voor smooth scrolling gebruikte Killian alleen CSS: html {scroll-behavior: smooth;} Hierdoor scrollt de browser automatisch met een animatie naar een sectie van de pagina. Hiervoor hoef je dus geen JavaScript meer te gebruiken.

  • Reduce motion

    Als iemand “reduce motion” heeft aangezet in zijn browser of besturingssysteem, worden animaties uitgeschakeld. Dit is belangrijk voor toegankelijkheid en gebruiksvriendelijkheid. @media (prefers-reduced-motion: no-preference) {html {scroll-behavior: smooth;}}

  • Scroll-margin

    Met scroll-margin kan je voorkomen dat content onder een sticky header verdwijnt wanneer je naar een ankerlink scrollt.

  • Accordions met details en summary

    Killian liet zien dat je tegenwoordig accordions kunt maken met alleen HTML, zonder JavaScript te gebruiken. Met de elementen details en summary kan je eenvoudig een uitklapbaar onderdeel maken waarbij alleen de titel zichtbaar is totdat iemand erop klikt. Wanneer het onderdeel geopend wordt, voegt de browser automatisch een open status toe. Daarnaast kan je het standaard pijltje aanpassen met CSS. Ook liet hij zien dat je met het name attribuut meerdere accordions aan elkaar kunt koppelen, zodat er maar één tegelijk open kan staan. Open je een nieuwe accordion, dan sluit de vorige automatisch.

    HTML

    De browser regelt zelf het openen en sluiten.

    CSS

    Met CSS kun je de open status en het pijltje stylen.

    Geen JavaScript

    Door hetzelfde name attribuut blijft er maar een item open.

    <details name="accordion-demo">
    <summary>HTML</summary>
    <p>Content van de accordion.</p>
</details>

  • Dialog

    Tot slot vertelde hij over het dialog element. Dit is eigenlijk een ingebouwde popup van HTML. Het element is standaard verborgen totdat je het opent. Met :backdrop kan je de achtergrond achter de popup stijlen, bijvoorbeeld donker maken. Ook @starting-style kan gebruikt worden om dialogs te animeren.

    Native dialog

    Dit venster gebruikt het HTML dialog element en een gestylde backdrop.

     
    <dialog>
    <p>Dit is een native dialog.</p>
</dialog>

dialog::backdrop {
    background: rgba(0, 0, 0, 0.65);
}

Wat neem ik mee

Na deze Weekly Nerd wil ik bewuster omgaan met het gebruik van JavaScript. Ik wil eerst kijken of iets met HTML en CSS opgelost kan worden voordat ik direct JavaScript toevoeg. Daarnaast wil ik meer aandacht besteden aan accessibility, bijvoorbeeld door betere focus states toe te voegen en rekening te houden met gebruikers die minder animaties willen zien.

Peter Paul Koch

Browser history

Wat hij vertelde

Tijdens deze Weekly Nerd vertelde Peter-Paul Koch over de geschiedenis van browsers en hoe browsers websites renderen. Hij legde uit welke onderdelen een browser heeft, zoals HTML, CSS, de DOM en de rendering engine. Ook vertelde hij over render blocking. CSS en JavaScript kunnen ervoor zorgen dat een pagina later geladen wordt. Daarom zijn technieken zoals async en defer belangrijk voor performance. Daarnaast ging hij in op backward compatibility. Browsers blijven oude code ondersteunen zodat oude websites nog steeds blijven werken.

Belangrijke inzichten

  • Rendering engine

    Verantwoordelijk voor het verwerken van HTML en CSS en het renderen van de pagina. Browsers zoals Chrome gebruiken hiervoor Blink.

  • AOM (Accessibility Object Model)

    Naast de DOM bouwt de browser ook een AOM op. Deze wordt gebruikt door screenreaders en andere accessibility tools. Core vs DOM

  • JavaScript Core

    JavaScript Core gaat over de programmeertaal zelf, zoals variabelen en functies. De DOM zorgt ervoor dat JavaScript HTML-elementen kan aanpassen.

  • Render Blocking

    CSS blokkeert standaard rendering. JavaScript ook, tenzij je async of defer gebruikt. defer: uitvoeren nadat de DOM geladen is.

  • Backward compatibility

    Browsers blijven oude technieken ondersteunen zodat oude websites nog steeds blijven werken. Zoals het gebruiken van body bgcolor=“abdaca”>/body>

Wat neem ik mee

Ik neem vooral mee dat browsers veel complexer zijn dan ik eerst dacht. Er gebeurt veel meer achter de schermen voordat een website zichtbaar wordt.

Nils Binder

9elements

Wat hij vertelde

Tijdens deze Weekly Nerd vertelde Nils Binder over zijn bedrijf 9elements en liet hij verschillende projecten zien. Hij vertelde hoe design en development binnen hun team samenwerken om creatieve websites te bouwen. Wat ik interessant vond was dat een Figma design vaak nog erg verandert tijdens development. Het eindproduct ziet er dus niet altijd precies hetzelfde uit als het eerste ontwerp. Ook vertelde hij dat het web tegenwoordig meer mogelijkheden heeft dan Figma. Vroeger konden designs uit Photoshop vaak niet volledig op het web gemaakt worden, maar nu is dat juist andersom. Daarnaast liet hij moderne CSS technieken zien zoals subgrid, view transitions en steps animations.

Belangrijke inzichten

  • Figma lijkt op CSS

    Figma lijkt op CSS, omdat het principes gebruikt die overeenkomen met hoe je websites bouwt. Zoals auto layout die op een manier werkt die lijkt op flexbox in CSS. Met het web kan je tegenwoordig meer dan in design tools zoals Figma. Niet alles wat met CSS mogelijk is, kan ook direct in Figma worden gemaakt. Vroeger was dat andersom, toen konden designs vaak niet volledig op het web worden gerealiseerd.

  • Steps animations

    Met steps() kan je een animatie maken met meerdere afbeeldingen zodat het lijkt op een flipbook of 3D animatie/video.

    1 2 3 4 5 6 
    .steps-cube {
    animation: cube-steps 2s steps(8) infinite;
}

@keyframes cube-steps {
    to {
        transform: rotateX(360deg) rotateY(360deg);
    }
}

  • Subgrid

    Met subgrid kunnen child elementen dezelfde grid structuur gebruiken als de parent grid.

  • View Transitions

    Met view transitions kan de browser automatisch animaties maken tussen pagina’s zonder JavaScript frameworks.

  • ::first-line

    Met ::first-line kan je alleen de eerste regel van een tekst apart stylen.

    Deze eerste regel krijgt een andere stijl. De rest van deze tekst blijft normaal, waardoor je goed ziet dat ::first-line alleen invloed heeft op de eerste regel van een tekstblok. 

    .first-line-demo::first-line {
    color: #f2dcc3;
    font-weight: bold;
}

Wat neem ik mee

Ik neem vooral mee dat webdesign veel verder is dan alleen Figma namaken. CSS biedt tegenwoordig veel creatieve mogelijkheden die ik nog niet kende. Daarnaast wil ik meer experimenteren met moderne CSS features zoals subgrid en view transitions om creatievere websites te bouwen.

Robert Broersma

FF formulieren maken

Wat hij vertelde

Tijdens deze Weekly Nerd vertelde Robert Broersma over het ontwerpen van goede formulieren. Hij legde uit dat formulieren niet alleen bestaan uit invoervelden, maar dat gebruiksvriendelijkheid en toegankelijkheid een grote rol spelen. Hij vertelde bijvoorbeeld dat je alleen informatie moet vragen die echt nodig is. Ook is het belangrijk om autocomplete te gebruiken, duidelijke foutmeldingen te tonen en invoervelden logisch te ordenen. Daarnaast ging hij in op accessibility, zoals voldoende kleurcontrast, duidelijke labels en grote klikvlakken voor gebruikers.

Belangrijke inzichten

  • Vraag alleen wat nodig is

    Vraag alleen gegevens die echt noodzakelijk zijn. Volgens de wet mag je geen onnodige informatie verzamelen. Geef daarnaast duidelijk aan welke velden optioneel zijn, in plaats van alle verplichte velden te markeren.

  • Maak Invullen Makkelijk

    Gebruik autocomplete en zorg voor grote klikvlakken van ongeveer 44x44px. Dit maakt formulieren sneller, toegankelijker en prettiger om in te vullen.

  • Zorg Voor Duidelijke Structuur

    Elk invoerveld moet een zichtbaar label hebben en de velden moeten in een logische volgorde staan. Daardoor voelt het formulier natuurlijker aan en begrijpen gebruikers sneller wat ze moeten doen.

  • Help Gebruikers Bij Fouten En Onderbrekingen

    Na het verzenden/of direct bij het invullen moet duidelijk zichtbaar zijn welke velden fouten bevatten. Bij langere formulieren is het handig als gebruikers hun voortgang kunnen opslaan en later verder kunnen gaan.

Wat neem ik mee

Ik neem vooral mee dat kleine details een formulier veel gebruiksvriendelijker maken. Dingen zoals autocomplete, duidelijke labels en goede foutmeldingen maken een groot verschil voor de gebruiker. Daarnaast wil ik bij toekomstige formulieren meer rekening houden met toegankelijkheid en duidelijkheid.

  • Snelle En Lichte Websites

    Static site generators maken websites sneller en lichter. Omdat er minder serverwerk nodig is, gebruiken deze websites vaak ook minder energie.

  • Duurzamer Webdesign

    Je kunt websites efficiënter maken door afbeeldingen te comprimeren, lazy loading te gebruiken en system fonts te kiezen. Daardoor laadt de website sneller en verbruikt hij minder data en energie.

  • Hergebruik En Toegankelijkheid

    Oude computers kunnen nog goed gebruikt worden als server in plaats van weggegooid te worden. Daarnaast kan je met prefers-reduced-motion animaties uitschakelen voor gebruikers die gevoelig zijn voor

Wat neem ik mee

Ik neem vooral mee dat het belangrijk is om technologie beter te begrijpen in plaats van alleen te gebruiken en dat je oude tech nog prima kan gebruiken voor onderdelen of anderen doeleinde.

Johan

Stichting Accessibility

Wat hij vertelde

WCAG is een goede basis, maar kan je ook verkeerd kunt interpreteren.

Tijdens deze Weekly Nerd vertelde Johan over web accessibility en hoe mensen met beperkingen websites gebruiken. Hij liet een screenreader demonstratie zien op de website van Bol.com. Het ging erg snel waardoor ik niet alles kon volgen, maar je hoorde goed hoeveel links en onderdelen een screenreader opleest. Hij vertelde ook dat je toegankelijkheid niet goed kunt ontwerpen zonder feedback van de mensen die deze hulpmiddelen echt gebruiken. Daarnaast besprak hij de vier basisprincipes van de WCAG:
- Perceivable: Informatie moet waarneembaar zijn, bijvoorbeeld door tekstalternatieven voor afbeeldingen.
- Operable: Gebruikers moeten de interface kunnen bedienen, bijvoorbeeld met een toetsenbord.
- Understandable: Informatie en bediening moeten begrijpelijk zijn, bijvoorbeeld door duidelijke taal en consistente navigatie.
- Robust: Inhoud moet robuust genoeg zijn om betrouwbaar te werken.

Belangrijke inzichten

  • Bouw Op Bestaande Hulpmiddelen

    Screenreaders hebben al veel ingebouwde functies. Daarom hoef je niet overal extra skiplinks of hulpmiddelen toe te voegen. Decoratieve afbeeldingen hoeven ook geen beschrijvende alt-tekst te hebben. Een lege alt is dan voldoende.

  • Test Met Echte Gebruikers

    Toegankelijkheid testen werkt het beste samen met mensen die daadwerkelijk beperkingen hebben. Zij ervaren problemen die je zelf vaak niet ziet tijdens het bouwen.

  • Zorg Voor Duidelijke Navigatie En Structuur

    Gebruikers van screenreaders navigeren vaak met headings door een pagina. Daarom is een logische heading structuur belangrijk. Ook moeten gebruikers informatie snel kunnen vinden zonder te veel stappen of klikken.

  • Maak De Interface Rustig En Bedienbaar

    Duidelijke focus state helpen gebruikers die met een toetsenbord navigeren. Vermijd daarnaast te veel animaties, kleuren, advertenties, sticky headers en bewegende elementen, omdat die websites onbruikbaar of vervelend kunnen maken voor sommige gebruikers.

Wat neem ik mee

Ik neem vooral mee dat toegankelijkheid veel verder gaat dan alleen WCAG regels volgen. Het belangrijkste is begrijpen hoe echte gebruikers websites ervaren. Daarnaast wil ik meer testen met screenreaders en beter nadenken over rust, duidelijkheid en navigatie in mijn designs.

Privacy van Hans de Zwart

Tijdens deze sessie stond privacy centraal. Hans liet zien dat privacy veel meer is dan alleen het beschermen van persoonsgegevens. Het gaat over controle, verwachtingen en de mogelijkheid om jezelf vrij te kunnen ontwikkelen zonder voortdurend geobserveerd te worden. Daarbij werd uitgelegd hoe privacy niet alleen een persoonlijk recht is, maar ook een belangrijke rol speelt binnen de samenleving.

Wat hij vertelde

Hans begon met de vraag wat privacy eigenlijk betekent. Vaak wordt privacy gezien als het afschermen van persoonlijke gegevens, maar volgens hem is het concept veel groter. Privacy heeft te maken met de verschillende rollen die mensen in hun dagelijks leven aannemen. De informatie die je deelt met een arts verschilt bijvoorbeeld met wat je deelt met collega's, vrienden of onbekenden. Het probleem ontstaat wanneer informatie buiten de context terechtkomt waarvoor deze oorspronkelijk bedoeld was.


Een belangrijk begrip dat werd besproken was contextuele integriteit. Hierbij draait het om de verwachting dat informatie binnen de juiste context blijft. Wanneer je een brood koopt bij de bakker verwacht je niet dat die gegevens worden vastgelegd of gedeeld met andere partijen. Privacy gaat daarom niet alleen over geheimhouding, maar vooral over passende omgang met informatie.


Ook werd de Algemene Verordening Gegevensbescherming (AVG) besproken. Hans omschreef de AVG als een verzameling regels die eigenlijk grotendeels gebaseerd zijn op gezond verstand. Organisaties mogen persoonsgegevens alleen verzamelen wanneer daar een duidelijke reden voor bestaat en moeten zorgvuldig omgaan met de gegevens die zij verwerken.

Belangrijke inzichten

  • Privacy Gaat Verder Dan Persoonsgegevens

    Privacy draait niet alleen om welke data wordt opgeslagen, maar ook om de controle die mensen hebben over hun eigen informatie en identiteit.

  • Context Bepaalt Wat Acceptabel Is

    Informatie die binnen de ene situatie normaal is om te delen, kan in een andere situatie ongepast zijn. Privacy gaat daarom sterk over verwachtingen en context.

  • Privacy Ondersteunt Een Vrije Samenleving

    Mensen moeten de ruimte hebben om ideeën te ontwikkelen, keuzes te maken en meningen te vormen zonder voortdurend gemonitord te worden.

  • De AVG Beschermt Gebruikersrechten

    Gebruikers hebben recht op inzage, correctie, verwijdering en overdraagbaarheid van hun gegevens. Hierdoor behouden zij meer controle over hun persoonlijke informatie.

  • Doelbinding Is Essentieel

    Gegevens mogen alleen worden gebruikt voor het doel waarvoor ze zijn verzameld. Het verzamelen van data betekent niet automatisch dat deze voor andere doeleinden mag worden ingezet.

  • Privacy By Design Begint Bij Technische Keuzes

    Ontwikkelaars kunnen privacy vanaf het begin meenemen in hun ontwerpen door bewust om te gaan met dataopslag en technieken zoals hashes en blind signatures toe te passen.

Wat neem ik mee

Deze presentatie liet mij beseffen dat privacy niet alleen een juridisch onderwerp is, maar ook een belangrijk onderdeel van een goed ontwerp en verantwoord ontwikkelen. Als developer heb ik invloed op welke gegevens worden verzameld, hoe deze worden opgeslagen en wie toegang heeft. Daarom wil ik in toekomstige projecten bewuster nadenken over privacyvriendelijke oplossingen en het principe volgen dat alleen de gegevens worden verwerkt die echt noodzakelijk zijn.

De Voorhoede

Tijdens de bezoek aan De Voorhoede kregen we een kijkje in hoe moderne webtechnologieën worden toegepast in echte projecten. De presentatie behandelde verschillende onderwerpen, waaronder geavanceerde CSS-technieken, het werken met het NL Design System en het ontwikkelen van Progressive Web Apps volgens het offline first-principe. Het centrale thema was het bouwen van websites en applicaties die niet alleen mooi en consistent zijn, maar ook betrouwbaar blijven functioneren onder verschillende omstandigheden.

Wat er verteld werd

De presentatie begon met een aantal CSS-technieken die werden gebruikt in projecten van De Voorhoede. Hierbij werd onder andere uitgelegd hoe pseudo-elementen zoals ::after kunnen worden ingezet om visuele effecten toe te voegen zonder extra HTML-elementen. In combinatie met clip-path kunnen complexe vormen en animaties worden gemaak.


Vervolgens werd ingegaan op het NL Design System. Hierbij werd uitgelegd hoe verschillende organisaties dezelfde design tokens en componenten kunnen hergebruiken om consistente interfaces te bouwen. In plaats van steeds nieuwe stijlen te ontwerpen, wordt er gewerkt met bestaande tokens voor kleuren, spacing en typografie. Wanneer er verbeteringen nodig zijn, gebeurt dit via pull requests zodat de kwaliteit van het systeem behouden blijft.


Het laatste deel van de presentatie ging over Progressive Web Apps en offline first ontwikkelen. De spreker benadrukte dat ontwikkelaars er niet vanuit moeten gaan dat gebruikers altijd internet hebben. Door gegevens tijdelijk lokaal op te slaan en later te synchroniseren, blijven applicaties bruikbaar wanneer een verbinding wegvalt. Dit is vooral belangrijk voor toepassingen die buiten kantooromgevingen worden gebruikt.

Belangrijke inzichten

  • Moderne CSS kan veel problemen oplossen zonder extra HTML

    Met pseudo-elementen zoals ::after kunnen visuele effecten worden toegevoegd zonder extra markup. Hierdoor blijft de HTML schoner en wordt styling vooral in CSS opgelost. 

    .title::after {
    content: "";
    position: absolute;

Q42

Deze bezoek bij Q42 ging over het opzetten en onderhouden van een design system. Daarbij werd gekeken naar hoe designers en developers beter kunnen samenwerken door gebruik te maken van een duidelijke structuur in Figma en het inzetten van design tokens. De spreker introduceerde het maturity level framework van Q42, waarmee teams kunnen beoordelen hoe goed hun design workflow is ingericht en hoe consistent designbeslissingen worden doorvertaald naar code.

Wat er verteld werd

Tijdens de presentatie werd uitgelegd dat een goed design system veel verder gaat dan alleen een verzameling componenten. De basis begint bij een sterke foundation layer waarin zaken zoals kleuren, typografie, spacing en andere ontwerpprincipes worden vastgelegd. Vanuit deze basis worden vervolgens kleinere herbruikbare onderdelen opgebouwd, ook wel atoms genoemd.


Een belangrijk onderdeel van de sessie was het gebruik van design tokens. Dit zijn gestandaardiseerde waarden die zowel door designers als developers gebruikt kunnen worden. Wanneer deze tokens rechtstreeks vanuit Figma worden gegenereerd, ontstaat er minder kans op fouten en blijven designs consistenter tijdens de ontwikkeling.


Daarnaast werd het maturity level framework besproken. Dit framework helpt teams om te beoordelen hoe volwassen hun design system is. Hierbij wordt gekeken naar de structuur van Figma-bestanden, de kwaliteit van componenten en de manier waarop design tokens worden beheerd en gebruikt binnen projecten.

Belangrijke inzichten

  • Een sterke foundation zorgt voor consistentie

    Alle componenten bouwen voort op dezelfde basiswaarden voor kleuren, spacing en typografie. Hierdoor ontstaat een uniforme gebruikerservaring en hoeft niet elk onderdeel opnieuw vanaf nul ontworpen te worden. 

    :root {
    --color-primary: #0066cc;
    --spacing-md: 24px;
    --font-size-body: 16px;
}

  • Design tokens verbinden design en development

    Door tokens vanuit Figma te exporteren gebruiken designers en developers exact dezelfde waarden. Een kleur, spacing of font-size wordt dan niet handmatig overgenomen, maar direct gekoppeld aan dezelfde bron. 

    .button {
    background: var(--color-primary);
    padding: var(--spacing-md);
}

  • Atoms vormen de bouwstenen van een design system

    Kleine, herbruikbare onderdelen zoals knoppen, iconen en invoervelden vormen de basis voor grotere componenten en pagina's. Door deze onderdelen goed op te zetten blijft het systeem schaalbaar en overzichtelijk.

  • Een maturity framework helpt bij groei

    Door regelmatig te evalueren hoe een design system is opgezet, kunnen teams verbeterpunten identificeren. Zo wordt duidelijk waar de workflow consistenter, professioneler of beter geautomatiseerd kan worden.

Wat neem ik mee

Deze bezoek maakte duidelijk hoe belangrijk een goed georganiseerd design system is voor de samenwerking tussen designers en developers. Vooral het gebruik van design tokens vond ik interessant, omdat hiermee ontwerpkeuzes automatisch kunnen worden vertaald naar code. Ik neem mee dat een sterke foundation en consistente tokens niet alleen zorgen voor een efficiënter ontwikkelproces, maar ook voor een betere en meer uniforme gebruikerservaring.

The Web You Want (Dag 2)

Wat zij vertelde

Tijdens deze sessie sprak Leonie, die blind is, over de rol van AI bij het toegankelijker maken van het web voor mensen met een visuele beperking. Ze liet verschillende AI-tools zien die dagelijkse obstakels helpen overbruggen, zoals het beschrijven van afbeeldingen, het samenvatten van complexe documenten en het herkennen van producten en objecten in de fysieke wereld. Tegelijkertijd benadrukte ze dat AI niet de oplossing is voor slechte toegankelijkheid, maar eerder een hulpmiddel dat de tekortkomingen van het huidige web compenseert.

Belangrijke inzichten

  • AI lost symptomen op, niet het probleem

    AI kan ontbrekende toegankelijkheid deels compenseren, maar de echte oplossing blijft het bouwen van websites met goede semantische HTML, duidelijke structuur en correcte alt-teksten.

  • Toegankelijkheid is nog steeds een groot probleem

    Ongeveer 16% van de afbeeldingen op het web heeft geen alt-tekst en ongeveer 10% heeft een slechte beschrijving. Hierdoor missen gebruikers met een screenreader vaak belangrijke informatie.

  • Goede structuur maakt een groot verschil

    Documenten en websites moeten een logische heading-hiërarchie gebruiken. Wanneer elke paragraaf als een aparte heading wordt gemarkeerd, wordt navigeren met een screenreader onnodig moeilijk.

  • AI kan zelfstandigheid vergroten

    Technologieën zoals Meta Glasses, AI-assistenten en barcode scanners helpen mensen met een visuele beperking om zelfstandiger informatie te vinden en hun omgeving te begrijpen.

  • Verantwoord gebruik van AI is belangrijk

    Leonie benadrukte dat ze niet tegen AI is, maar tegen zinloos gebruik ervan. AI moet mensen ondersteunen waar nodig, niet gebruikt worden als excuus om toegankelijkheid te negeren.

Wat neem ik mee

Deze presentatie maakte duidelijk dat toegankelijkheid geen optionele extra is, maar een essentieel onderdeel van goed webdesign. Hoewel AI indrukwekkende oplossingen biedt voor mensen met een beperking, zou het ideaal zijn als deze hulpmiddelen minder nodig waren doordat websites vanaf het begin correct worden gebouwd. Als toekomstige developer wil ik daarom meer aandacht besteden aan semantische HTML, logische heading-structuren en kwalitatieve alt-teksten.


Daarnaast zie ik zelf dagelijks veel video's en content over AI op sociale media. Het is moeilijk te ontkennen dat AI ervoor zorgt dat je sneller kunt werken en in sommige gevallen zelfs betere resultaten kunt behalen. Na alles wat Leonie heeft verteld, ben ik niet van mening dat we AI moeten tegenwerken. Wel denk ik dat er duidelijke wet- en regelgeving nodig is om ervoor te zorgen dat AI op een verantwoorde manier wordt gebruikt. Tegelijkertijd geloof ik dat we moeten accepteren dat AI niet meer zal verdwijnen. Integendeel, de technologie zal alleen maar verder groeien en een steeds grotere rol spelen in ons dagelijks leven en werk. Daarom lijkt het mij belangrijker om AI op een verstandige manier te integreren en te gebruiken als aanvulling op menselijke vaardigheden, in plaats van het volledig af te wijzen. AI kan een krachtige aanvulling zijn, maar mag nooit een vervanging worden voor goede toegankelijkheid en verantwoord webdesign.
