Meesterproef

De opdracht

Voor dit project werken we voor de Gemeente Amsterdam. De opdracht is om een online platform te ontwerpen en ontwikkelen waarmee mensen met een lichamelijke beperking kunnen zien hoe toegankelijk locaties in Amsterdam zijn.

Met behulp van data van de Gemeente Amsterdam kunnen gebruikers zoeken naar locaties, filteren op verschillende toegankelijkheidskenmerken en direct informatie bekijken die aansluit bij hun behoeften. Het doel van het platform is om inwoners en bezoekers te helpen beter door de stad te navigeren en toegankelijkere keuzes te maken.

Tijdens het project houden we rekening met gebruiksvriendelijkheid, responsiveness en toegankelijkheid volgens de WCAG-richtlijnen. Het eindproduct moet een duidelijke en betrouwbare kaartervaring bieden die op verschillende apparaten goed werkt.

Mijn rol

Binnen het project was ik verantwoordelijk voor de ontwikkeling van de interactieve kaart en de koppeling tussen verschillende onderdelen van de applicatie. Ik heb de basisstructuur van de Leaflet-kaart opgezet, inclusief toegankelijkheidsverbeteringen en kaartconfiguraties. Daarnaast heb ik de filterfunctionaliteit in de sidebar ontwikkeld, waarbij gebruikers via een filtercascade relevante subcategorieën kunnen selecteren. Ook heb ik de communicatie tussen de sidebar en de kaart gerealiseerd met behulp van custom events, zodat filters dynamisch kaartlagen kunnen tonen, verbergen en resetten. Ook heb ik gewerkt aan de list-view, waarin dezelfde locaties als op de kaart toegankelijk worden weergegeven.

Leerdoelen

  • Tijdens de meesterproef wil ik beter worden in het plannen van mijn werkzaamheden en het inschatten van hoeveel tijd een functie kost om te maken. Ik wil taken minder uitstellen en op volgorde aanpakken. Ik ben snel geneigd om verschillende dingen te gelijk te doen waardoor ik de controlle verlies.

  • Tijdens de meesterproef wil ik mijn JavaScript-vaardigheden verder ontwikkelen door nieuwe en meer geavanceerde technieken te gebruiken die ik nog niet eerder heb toegepast. Denk hierbij aan technieken zoals het werken met API's, complexe event listeners, objecten, array-methodes, async/await en interactieve gebruikerservaringen. Aan het einde van de meesterproef wil ik deze technieken zelfstandig kunnen toepassen om dynamische en interactieve functionaliteiten te bouwen die verder gaan dan de basis van JavaScript.

  • Tijdens de meesterproef wil ik beter leren werken met GitHub branches en code conventions, zodat ik gestructureerder kan samenwerken binnen een team. Ik ga voor elke feature of taak een aparte branch gebruiken en werken met duidelijke commit messages en vaste code-afspraken binnen het project. Bij de hackaton ging dat helaas niet waardoor mijn groep en ik last minute in de problemen kwamen.

Uitdagingen

  • Werken met GitHub en branches

    Probleem

    Tijdens het project werkte iedereen aan zijn eigen onderdeel van de website. Hierdoor was het soms lastig om alle wijzigingen goed samen te voegen. Er was een risico dat code van teamgenoten elkaar zou overschrijven of dat er fouten zouden ontstaan bij het samenvoegen.

    Oplossing

    Om dit probleem te voorkomen werkte iedereen in een eigen branch binnen GitHub. Ik werkte eerst mijn taken uit in mijn eigen branch en voegde deze daarna samen met de DEV branch. Ook controleerde ik regelmatig of er nieuwe wijzigingen van mijn teamgenoten waren, zodat mijn code altijd up-to-date bleef. Hierdoor verliep het samenwerken een stuk makkelijker.

  • Op een lijn blijven binnen het project

    Probleem

    Tijdens het project had iedereen zijn eigen ideeën over hoe bepaalde onderdelen gemaakt moesten worden. Hierdoor kon soms onduidelijkheid ontstaan over de planning of de aanpak van een opdracht.

    Oplossing

    Om ervoor te zorgen dat iedereen op een lijn bleef, hadden we regelmatig overleg. Tijdens deze momenten bespraken we onze voortgang, de taken die nog gedaan moesten worden en eventuele problemen. Ook hielden we elkaar via GitHub en berichten op de hoogte van wijzigingen. Hierdoor wist iedereen waar de rest van het team mee bezig was en konden we goed samenwerken.

Nieuwe inzichten

  • Werken met custom events

    Tijdens dit project heb ik geleerd hoe verschillende onderdelen van een website met elkaar kunnen communiceren zonder direct aan elkaar gekoppeld te zijn. Hiervoor heb ik custom events gebruikt. Wanneer een gebruiker een filter selecteert in de sidebar, wordt er een event verstuurd naar de kaart.

    window.dispatchEvent(
    new CustomEvent("filter:show", {
        detail: { name: newFilter }
    })
);

    Door dit te gebruiken blijft de code overzichtelijk en is het makkelijker om later nieuwe functies toe te voegen.

  • Dynamische filters maken

    Ik heb geleerd hoe ik een formulier kan aanpassen op basis van keuzes van de gebruiker. Als een gebruiker een hoofdcategorie kiest, worden alleen de bijpassende subcategorieën getoond.

    subOptions.forEach((option) => {
    if (option.dataset.parent === gekozenHoofdCategorie) {
        subSelect.appendChild(option);
    }
});

    Hierdoor wordt de website gebruiksvriendelijker en krijgt de gebruiker alleen relevante opties te zien.

  • Toegankelijkheid verbeteren

    Tijdens het maken van de kaart heb ik geleerd hoe ik een website toegankelijker kan maken voor mensen die een screenreader gebruiken. Dit heb ik gedaan met behulp van ARIA-labels.

    <div
    id="map"
    role="region"
    aria-label="Interactieve kaart van Amsterdam">
</div>

    Door deze labels toe te voegen krijgen gebruikers van een screenreader meer informatie over de inhoud van de pagina.

  • Werken met de Leaflet-library

    Ik heb geleerd hoe ik een externe library, zoals Leaflet, kan gebruiken om een interactieve kaart te maken. Ook heb ik instellingen toegevoegd zodat gebruikers niet buiten Amsterdam kunnen navigeren.

    const map = L.map("map", {
    maxBounds: amsterdamBounds,
    maxBoundsViscosity: 1.0,
});

    Hierdoor heb ik meer ervaring opgedaan met het lezen van documentatie en het gebruiken van externe tools binnen een project.

  • Werken met dispatchEvent()

    Tijdens dit project heb ik geleerd hoe ik met dispatchEvent() een gebeurtenis kan versturen naar andere onderdelen van de applicatie. Hierdoor kunnen componenten informatie met elkaar delen zonder direct met elkaar verbonden te zijn.

    window.dispatchEvent(
    new CustomEvent("filter:hideAll")
);

    Met deze code wordt een event verstuurd waarmee alle actieve filters kunnen worden uitgezet. Ik heb geleerd dat dit een handige manier is om acties tussen verschillende onderdelen van een applicatie te laten samenwerken. Hierdoor blijft de code overzichtelijk en makkelijker te onderhouden.

Reflectie

Tijdens dit project heb ik veel geleerd over het bouwen van een interactieve webapplicatie. Wat ik lastig vond, was het laten samenwerken van verschillende componenten, zoals de sidebar en de kaart. Vooral het werken met custom events was in het begin even wennen, omdat ik deze techniek nog niet eerder had gebruikt. Ook het gebruiken van dispatchEvent() was nieuw voor mij.

Wat goed ging, was het ontwikkelen van de kaart, de filters en de list-view. Ook vond ik het leuk om samen te werken via GitHub. Voor het eerst heb ik gewerkt met branches, pull requests en een code review uitgevoerd. Hierdoor heb ik beter geleerd hoe ontwikkelaars samenwerken aan een project.

Wat ik zeker meeneem naar toekomstige projecten, is het werken met GitHub, het uitvoeren van code reviews en het gebruik van custom events om componenten met elkaar te laten communiceren. Daarnaast neem ik mee hoe belangrijk het is om toegankelijkheid tijdens het ontwikkelen van een website direct mee te nemen.

Tijdens het testen met Berend benadrukte hij hoe goed hij onze webapp kon gebruiken, omdat deze al heel toegankelijk was. Dat liet mij zien dat toegankelijkheid niet iets is wat je pas achteraf toevoegt, maar iets wat vanaf het begin invloed heeft op hoe bruikbaar een project is.

Evaluatie van mijn leerdoelen

Plannen en inschatten van werkzaamheden

Hier heb ik hard aan gewerkt. Tijdens de meesterproef heb ik taken opgepakt en verdeeld over verschillende weken. Voordat we begonnen met werken hebben we gezamenlijk de taken van die week besproken en verdeeld tussen de teamleden. Dit hebben we in onze Notion bijgehouden, waar we ook een agenda bijhielden voor onze afspraken met onze coach en opdrachtgever. Bij andere projecten hield ik mij niet echt aan een planning of agenda, waardoor ik vaak in tijdsnood kwam. Ik heb echt vooruitgang geboekt bij dit leerdoel.

Mijn JavaScript-vaardigheden verder ontwikkelen

Hier heb ik goed aan gewerkt. Tijdens dit project heb ik nieuwe technieken gebruikt die ik eerder nog niet of nauwelijks had toegepast, zoals custom events, dispatchEvent(), DOM-manipulatie, dataset-attributen, dynamische filters en de communicatie tussen verschillende componenten. Hierdoor heb ik meer vertrouwen gekregen in het bouwen van interactieve functionaliteiten met JavaScript en heb ik meer over de mogelijkheden met JavaScript geleerd.

Beter leren werken met GitHub branches en code conventions

Hier heb ik goed aan gewerkt. Tijdens dit project heb ik gewerkt met branches en pull requests binnen GitHub. Ook heb ik voor het eerst een code review uitgevoerd op de code van groepsgenoten. Hierdoor heb ik geleerd hoe belangrijk het is om code te controleren voordat deze wordt samengevoegd met de hoofdbranch. Daarnaast heb ik meer ervaring opgedaan met samenwerken aan dezelfde repository zonder elkaars werk te overschrijven door branches te maken voor elke feature die wordt gemaakt.

Conclusie

Dit project heeft mij geholpen om zowel technisch als op het gebied van samenwerken te groeien. Vooral op het gebied van JavaScript en GitHub heb ik veel nieuwe ervaring opgedaan. Deze kennis en vaardigheden neem ik mee naar toekomstige projecten.
